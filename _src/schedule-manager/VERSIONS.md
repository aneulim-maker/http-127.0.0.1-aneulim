# schedule-manager 버전 이력

새 버전은 **파일명을 따로 만들고 기존 파일은 덮어쓰지 않습니다.**
원본(`_src/`)과 배포용 압축본(`schedule-manager/`)은 같은 파일명을 씁니다.
빌드 ID는 파일명 끝과 맞춥니다: `index-YYMMDD-XN.html` ↔ `EU-AUX-YYMMDD-XN`.

예외 — 공개 주소 `/schedule-manager/`가 여는 `index.html`(현재 버전)과 `index0.html`(직전 버전)은
원본 파일명이 다릅니다. 어느 원본에서 빌드하는지는 아래 표와 `deploy.mjs` TARGETS에 적혀 있습니다.

```
원본  _src/schedule-manager/<파일명>    (주석 포함 · 배포 안 됨)
          │  node build.mjs <원본> <출력> "Agent UX · 사람+에이전트 프로젝트 매니저" <빌드ID>
          ▼
출력  schedule-manager/<파일명>          (미니파이 · 배포 대상)
```

## 참고
- `index0.html`(원본 `_src/schedule-manager/index.html`) 한 파일 안에 9/14~9/15 작업(L0~L3 개편, 책임자 강등, 요약 대시보드)이 누적되어 있습니다. 그 사이 단계별 파일은 따로 남아 있지 않습니다.
- 모든 버전은 같은 브라우저 저장 데이터(`si-workforce-v1`)를 씁니다. 같은 브라우저에서 두 파일을 열면 같은 데이터로 비교됩니다.
- git에는 최초 커밋만 있고 이후 변경은 커밋되지 않았습니다.
